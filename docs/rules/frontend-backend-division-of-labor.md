## 1. 分工原则

- 前端负责展示、交互、传输和局部 UI 状态，不决定业务权限或保存业务真相。
- Go 负责公开入口、认证、业务状态、后端编排和全局调度；后端能力优先由 Go 实现。
- Python 负责被调用的模型、解析、嵌入、检索及单次 AIExecution，不创建第二个全局调度器。
- PostgreSQL 保存业务真相，Milvus 是可重建索引，Redis 是可丢弃的缓存/协调资源。

以上是目标边界。现有 Python 业务、文件系统文档状态和进程内后台执行尚待收编，不能按规则推定迁移已完成。

## 2. 按能力划分

| 能力 | 前端 | Go | Python |
| --- | --- | --- | --- |
| 认证与权限 | 登录交互、token 使用 | 校验身份与权限、账户管理 | 迁移期校验内部/残留接口权限 |
| 会话与偏好 | 展示、选择、编辑 | 业务读写与公开接口 | 迁移期追加问答与消息读取 |
| 文档摄取 | 上传及进度展示 | 目标编排、文档状态与生命周期 | 解析、清洗、分块、嵌入 |
| 检索与问答 | 问题、引用与过程展示 | 目标门面及请求生命周期 | 局部检索、模型调用、引用标签校验 |
| 工作区与研究任务 | 操作与结果呈现 | 目标业务真相、全局调度与恢复 | 单步 AI 执行与结构化结果 |
| 研究比较、写作、Radar | 目标产品交互 | 目标任务编排与状态 | 目标模型分析与生成 |

模块目标、依赖和提案见 [14 功能规划](../plans/14-feature-modules.md)；不在本页复制进度与文件计数。

## 3. 接管要求

1. 先检查现有调用方、输入输出、鉴权、限流、缓存、错误和取消语义，再修改实现归属。
2. 新接管或删路由同步 [route-ownership](../../contracts/route-ownership.md)，不能仅以路径可达验收。
3. 数据所有权看 [table-acl](../../contracts/table-acl.md) 并核实实际迁移和调用方；规划权限不是已实施权限。
4. 公共契约先对齐，再实现；禁止临时双写、旁路通知或仅为迁移占位的空表空接口。
5. 跨语言验证要覆盖真实业务和故障；mock 通过不代表接管完成。

## 4. 运行边界

dev compose 只起中间件，应用源码运行；prod compose 是部署形态。
Python 不作为浏览器直连的公共入口。绑定、代理与内部令牌按实际运行配置验证，不能只看拓扑图。
